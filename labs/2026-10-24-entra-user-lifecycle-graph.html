Entra ID User Lifecycle with Microsoft Graph PowerShell

Track: M365 & Entra · Builds on Lab 01 (on-prem AD onboarding)
⏱ 25–30 min Level: Entry Skill: cloud identity admin

The ticket

INC-0042 · Priority: P3
From: HR <hr@contoso.lab>
“New hire Lab Tester starts Monday in Help Desk and needs an M365 account in the Help Desk security group. Also, the same contractor is leaving Friday: please make sure access is cut off cleanly.”

Last lab you did this on-prem with New-ADUser. Lots of shops are cloud-only now, so today you do the full joiner/leaver flow in Entra ID (formerly Azure AD) with the Microsoft Graph PowerShell SDK. Same idea, different cmdlets.

Prerequisites (all free)

  • A test tenant where you're Global Admin or User Admin: a Microsoft 365 Developer Program sandbox if you qualify, or a free Entra ID tenant (comes with a free Azure account). Never a school or work tenant.
  • A lab VM (Hyper-V or VirtualBox, Windows 10/11 or Windows Server eval) with PowerShell 7. Your Lab 01 VM works fine.
  • Internet access from the VM.
⚠ Licensing step (6) needs a tenant with M365 licenses (dev sandbox). On a free Entra tenant, skip it; everything else works.

Steps

Install-Module Microsoft.Graph -Scope CurrentUser
Get-InstalledModule Microsoft.Graph | Select-Object Name, Version

It's big (lots of sub-modules), so give it a couple of minutes.

Connect-MgGraph -Scopes "User.ReadWrite.All","Group.ReadWrite.All","Organization.Read.All","User-PasswordProfile.ReadWrite.All"
Get-MgContext | Select-Object Account, TenantId, Scopes

Sign in with your test-tenant admin and accept the consent prompt.

$domain = (Get-MgDomain | Where-Object IsDefault).Id
$domain
$pw = @{ Password = "Lab-Temp!2026x"; ForceChangePasswordNextSignIn = $true }
$u = New-MgUser -DisplayName "Lab Tester" `
  -UserPrincipalName "lab.tester@$domain" `
  -MailNickname "lab.tester" `
  -AccountEnabled `
  -PasswordProfile $pw `
  -UsageLocation "US" `
  -Department "Help Desk" -JobTitle "IT Support Tech"
$u | Select-Object Id, DisplayName, UserPrincipalName

UsageLocation isn't optional in real life: you can't assign a license without it.

$g = New-MgGroup -DisplayName "LAB-HelpDesk" `
  -MailEnabled:$false -SecurityEnabled `
  -MailNickname "lab-helpdesk" `
  -Description "Lab 02 test group"
New-MgGroupMember -GroupId $g.Id -DirectoryObjectId $u.Id
Get-MgSubscribedSku | Select-Object SkuPartNumber, SkuId, ConsumedUnits
$sku = Get-MgSubscribedSku | Where-Object SkuPartNumber -eq "DEVELOPERPACK_E5"   # use whatever SKU you see above
Set-MgUserLicense -UserId $u.Id -AddLicenses @(@{ SkuId = $sku.SkuId }) -RemoveLicenses @()
Update-MgUser -UserId $u.Id -PasswordProfile @{
  Password = "Lab-Reset!2026y"; ForceChangePasswordNextSignIn = $true }

Real world: verify the caller's identity before you do this. That's the whole point of the ticket.

# 1) Block sign-in
Update-MgUser -UserId $u.Id -AccountEnabled:$false
# 2) Invalidate refresh tokens (forces re-auth everywhere)
Revoke-MgUserSignInSession -UserId $u.Id
# 3) Remove group membership
Remove-MgGroupMemberByRef -GroupId $g.Id -DirectoryObjectId $u.Id

Order matters: block first, then revoke, so they can't just sign right back in.

Verify it worked

Get-MgUser -UserId $u.Id -Property DisplayName,UserPrincipalName,AccountEnabled,Department,UsageLocation |
  Format-List DisplayName,UserPrincipalName,AccountEnabled,Department,UsageLocation

Expect AccountEnabled : False.

Get-MgGroupMember -GroupId $g.Id

Cleanup

Remove-MgUser  -UserId  $u.Id
Remove-MgGroup -GroupId $g.Id
# Deleted users sit in the recycle bin for 30 days. To purge now (needs Directory.ReadWrite.All):
# Remove-MgDirectoryDeletedItem -DirectoryObjectId $u.Id
Disconnect-MgGraph

Interview questions

  1. An employee was fired an hour ago and is still reading email on their phone. What do you do, and why isn't disabling the account enough?
    Hint: existing tokens stay valid until they expire; revoke sessions too.
  2. What's the difference between a security group and a Microsoft 365 group?
    Hint: permissions/licensing vs. shared mailbox, Teams, SharePoint.
  3. A user was deleted by mistake yesterday. Can you get them back?
    Hint: soft-delete, 30-day recycle bin, Deleted users in the admin center.
