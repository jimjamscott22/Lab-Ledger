Lab 11: Warm-up - Read Windows Event Logs

Warm-upWindowsTroubleshooting⏱ 10–15 min

Safe practice: Use a Windows lab VM or your own device. These steps read logs only. Do not clear logs or change audit settings; preserve evidence on any device you support.

Skill & Scenario

A user reports an unexpected restart. Practice finding recent events, filtering to errors, and recording the event ID and time without assuming that one event alone proves the cause.

Time Estimate

10–15 minutes.

Prerequisites

  • Windows 10 or 11.
  • Windows PowerShell or PowerShell 7; administrator rights are not required for the System log on a typical personal/lab device.

Steps

Get-WinEvent -ListLog System |
  Select-Object LogName, RecordCount, IsEnabled
Get-WinEvent -LogName System -MaxEvents 1 |
  Select-Object TimeCreated, Id, LevelDisplayName, ProviderName

Expect the System log status and, if events exist, one recent event with a timestamp and ID.

Get-WinEvent -LogName System -MaxEvents 5 |
  Select-Object TimeCreated, Id, LevelDisplayName, ProviderName

Look at when events occurred, their IDs, severity, and provider. Informational events are common.

$since = (Get-Date).AddDays(-7)
Get-WinEvent -FilterHashtable @{
  LogName = 'System'
  Level = 1, 2
  StartTime = $since
} -MaxEvents 10 |
  Select-Object TimeCreated, Id, LevelDisplayName, ProviderName, Message

Expect up to ten matching events. No results is a valid outcome; widen the time window only if the exercise requires more examples.

eventvwr.msc

In Windows Logs, select System and compare the time and event ID with PowerShell output. Close Event Viewer when finished.

Verify it worked

  • You found the System log and know how to view its newest entries.
  • You can explain the event time, ID, level, and provider.
  • You filtered errors without clearing or editing the log.

Cleanup / rollback

No cleanup is needed: the commands and Event Viewer inspection are read-only.

Why this matters on the job

Logs provide a timeline that can confirm or challenge a user's recollection. Recording the event ID, source, and time helps support a clear escalation rather than a guess.

Prepares you for

  • Lab 04: Triage a "My PC Is So Slow" Ticket on Windows 11 — filtering recent System events while diagnosing a slow PC.
  • Lab 07: PC Won't Wake From Sleep After a Hardware Upgrade — using event timestamps and power-related evidence.

Interview questions

Why should you record an event's timestamp and provider as well as its ID?

The timestamp helps correlate events with the reported issue, and the provider identifies which Windows component recorded it.

Does an error event automatically identify the root cause?

No. It is one clue to correlate with the timeline, other events, and reproducible symptoms.
