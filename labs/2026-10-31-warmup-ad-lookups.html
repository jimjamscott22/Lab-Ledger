Lab 09: Warm-up - Read-Only Active Directory Lookups

Warm-upActive DirectoryPowerShell⏱ 10–15 min

Safe practice: Run these read-only commands only in an isolated practice domain where you have permission. Do not query an employer or production directory. No account or group is created or changed.

Skill & Scenario

A caller asks whether a practice account exists and which groups it belongs to. Learn the read-only Active Directory queries used to verify identity and access before taking action.

Time Estimate

10–15 minutes.

Prerequisites

  • An isolated lab.local domain from Lab 01, or another disposable practice domain.
  • PowerShell on a domain controller or a domain-joined computer with RSAT and the ActiveDirectory module.
  • At least one practice user and group to inspect.

Steps

Import-Module ActiveDirectory
Get-ADDomain | Select-Object DNSRoot, NetBIOSName

Expect the DNS and short names of your practice domain (for example, lab.local and LAB).

Get-ADUser -Filter 'Name -like "*Taylor*"' |
  Select-Object Name, SamAccountName, Enabled

If you completed Lab 01, the result should include Taylor Reed. Otherwise use a name that exists in your lab.

Get-ADPrincipalGroupMembership -Identity treed |
  Select-Object Name, GroupScope, GroupCategory

Replace treed with the practice user's SamAccountName. Expect the groups assigned to that user.

Get-ADGroup -Filter 'Name -like "*Marketing*"' |
  Select-Object Name, GroupScope, GroupCategory
Get-ADGroupMember -Identity GG_Marketing_Share_RW |
  Select-Object Name, SamAccountName, objectClass

Use a group that exists in your lab if the example Marketing group is not present.

Verify it worked

  • The domain name matched your practice environment.
  • The user query returned a name and account status (or clearly returned no matches).
  • The group lookup listed members and did not change directory data.

Cleanup / rollback

No cleanup is needed: all commands in this warm-up only read directory information.

Why this matters on the job

Confirming the exact account and group membership before changing access helps prevent mistaken resets, duplicate accounts, and over-broad permissions.

Prepares you for

  • Lab 02: Entra ID User Lifecycle with Microsoft Graph PowerShell — validating identity and group membership in a cloud directory.

Interview questions

Why should you verify a user's identity before changing their account?

It reduces the risk of making a sensitive change to the wrong account and supports the organization's identity-verification process.

What is the difference between looking up group membership and changing it?

A lookup gathers evidence; adding or removing membership changes access and requires authorization and verification.
