Lab 12: Warm-up - Linux Files and Permissions

Warm-upLinuxPermissions⏱ 10–15 min

Safe practice: Run this in a disposable Linux VM or container as a regular user. It creates a private temporary directory and file only. Do not use sudo, edit system files, or change permissions outside that directory. Check the directory path before cleanup.

Skill & Scenario

A teammate cannot read a shared file. Practice checking your identity, group membership, and file mode bits, then make a controlled permission change to a temporary file and verify the result.

Time Estimate

10–15 minutes.

Prerequisites

  • A Linux shell, such as Ubuntu in a disposable VM or container.
  • Basic command-line access as a regular user; no root or sudo access is needed.

Steps

id
groups
pwd

Expect your numeric user/group IDs, group names, and current working directory.

LAB_DIR=$(mktemp -d)
printf 'practice file\n' > "$LAB_DIR/notes.txt"
printf 'Temporary directory: %s\n' "$LAB_DIR"
ls -la "$LAB_DIR"

Keep this shell open so LAB_DIR remains set. The file is inside a newly created temporary directory.

stat -c '%A %a %U:%G %n' "$LAB_DIR/notes.txt"
ls -ld "$LAB_DIR"

Expect a permission string such as -rw-------, an octal mode, and the owner/group.

chmod 600 "$LAB_DIR/notes.txt"
stat -c '%A %a %U:%G %n' "$LAB_DIR/notes.txt"
cat "$LAB_DIR/notes.txt"

The mode should now be -rw------- (600), and the owner can still read the practice text.

Verify it worked

  • id showed your current account and groups.
  • stat displayed the file owner and mode.
  • After chmod 600, only the file owner has read/write permission; the owner can still read it.

Cleanup / rollback

Confirm that LAB_DIR is the temporary path printed in Step 2 before running cleanup. This removes only the directory created for this exercise:

printf 'Removing: %s\n' "$LAB_DIR"
rm -r -- "$LAB_DIR"
unset LAB_DIR

Why this matters on the job

Checking ownership and permissions before changing them helps diagnose access issues while avoiding broad, unsafe permission changes.

Prepares you for

  • Lab 06: Linux Users, Shared Folders & Least-Privilege sudo — reading user/group information and understanding Linux permission modes.

Interview questions

What does a mode of 600 allow?

The file owner can read and write it; the group and other users have no permissions.

Why inspect ownership and permissions before changing them?

It identifies the access problem and helps avoid granting more access than necessary.
