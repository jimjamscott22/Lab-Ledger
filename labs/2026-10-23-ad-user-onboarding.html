Lab 01: Active Directory User Onboarding with PowerShell

Help DeskActive DirectoryPowerShell⏱ 20–30 min

Lab only. Run these commands only on your isolated practice domain (lab.local). Never on a production or employer system.

Skill & Scenario

Skill: Create and manage AD objects (OU, security group, user), manage group membership, and handle password resets and lockouts using the ActiveDirectory PowerShell module.

Ticket #10423 – Priority: Normal
"Hi IT, our new Marketing Coordinator Taylor Reed starts Monday. Please create their account and give them access to the Marketing share. Thanks! — Dana, Marketing Manager"

Time Estimate

20–30 minutes (plus ~45 min one-time if you still need to build the DC).

Prerequisites (all free)

  • Hyper-V (Windows Pro) or VirtualBox.
  • Windows Server 2022 Evaluation ISO (180-day, free from Microsoft Evaluation Center).
  • A VM promoted to a domain controller for lab.local.
Not built yet? Quick DC setup

Install Server 2022 (Desktop Experience), set a static IP, rename it, then in an elevated PowerShell:

Rename-Computer -NewName DC01 -Restart
Install-WindowsFeature AD-Domain-Services -IncludeManagementTools
Install-ADDSForest -DomainName "lab.local" -DomainNetbiosName "LAB" -InstallDns
# Enter a DSRM password when prompted; the server reboots as a DC.

Run everything below in an elevated PowerShell on DC01 (or RSAT on a domain-joined client).

Steps

Import-Module ActiveDirectory
Get-ADDomain | Select-Object DNSRoot, DistinguishedName

Expect lab.local / DC=lab,DC=local.

New-ADOrganizationalUnit -Name "Marketing" -Path "DC=lab,DC=local" `
  -Description "Marketing department users and groups" `
  -ProtectedFromAccidentalDeletion $true
New-ADGroup -Name "GG_Marketing_Share_RW" -SamAccountName "GG_Marketing_Share_RW" `
  -GroupCategory Security -GroupScope Global `
  -Path "OU=Marketing,DC=lab,DC=local" `
  -Description "Read/Write access to \\fileserver\Marketing"

Tip: in real life you'd grant NTFS/share permissions to this group, never to individual users.

New-ADUser -Name "Taylor Reed" -GivenName "Taylor" -Surname "Reed" `
  -SamAccountName "treed" -UserPrincipalName "treed@lab.local" `
  -DisplayName "Taylor Reed" -Title "Marketing Coordinator" -Department "Marketing" `
  -Path "OU=Marketing,DC=lab,DC=local" `
  -AccountPassword (Read-Host -AsSecureString "Initial password") `
  -ChangePasswordAtLogon $true -Enabled $true

Use a password that meets domain complexity (e.g., 12+ chars, mixed types) or the command fails.

Add-ADGroupMember -Identity "GG_Marketing_Share_RW" -Members "treed"

Optionally trigger a lockout first by failing logon as LAB\treed from a client (if a lockout policy is set). Then:

# Check lock status
Get-ADUser treed -Properties LockedOut, BadLogonCount, LastBadPasswordAttempt |
  Select-Object SamAccountName, LockedOut, BadLogonCount, LastBadPasswordAttempt

# Reset the password and force change at next logon
Set-ADAccountPassword -Identity treed -Reset `
  -NewPassword (Read-Host -AsSecureString "New temporary password")
Set-ADUser -Identity treed -ChangePasswordAtLogon $true

# Unlock the account
Unlock-ADAccount -Identity treed

Help-desk habit: verify the caller's identity before any reset.

Verify It Worked

Get-ADOrganizationalUnit -Filter 'Name -eq "Marketing"' |
  Select-Object Name, DistinguishedName, ProtectedFromAccidentalDeletion

Get-ADGroup GG_Marketing_Share_RW -Properties Description |
  Select-Object Name, GroupCategory, GroupScope, Description

Get-ADUser treed -Properties Title, Department, Enabled, LockedOut, PasswordLastSet, pwdLastSet, MemberOf |
  Select-Object Name, UserPrincipalName, Title, Department, Enabled, LockedOut, PasswordLastSet, pwdLastSet, MemberOf

Get-ADGroupMember GG_Marketing_Share_RW | Select-Object Name, SamAccountName
  • OU exists and is protected = True
  • Group is Security / Global
  • User is Enabled, not LockedOut, pwdLastSet = 0 (must change at logon), MemberOf lists the group

Cleanup

Remove-ADUser -Identity treed -Confirm:$false
Remove-ADGroup -Identity GG_Marketing_Share_RW -Confirm:$false

# The OU is protected — this will fail with "Access is denied" until you clear the flag:
Set-ADOrganizationalUnit -Identity "OU=Marketing,DC=lab,DC=local" -ProtectedFromAccidentalDeletion $false
Remove-ADOrganizationalUnit -Identity "OU=Marketing,DC=lab,DC=local" -Recursive -Confirm:$false

# Confirm it's gone (should return nothing)
Get-ADOrganizationalUnit -Filter 'Name -eq "Marketing"'

Interview Questions

1. A user says they're locked out. What do you check, and in what order?

Verify identity, check LockedOut/BadLogonCount/LastBadPasswordAttempt, unlock, reset only if they forgot the password, and look for the lockout source (stale creds on phone, mapped drive, service) if it recurs.

2. Why assign share permissions to a group instead of the user?

Scalability and auditability: onboarding/offboarding is a single membership change, permissions stay consistent, and it follows AGDLP/RBAC best practice.

3. What's the difference between Global and Domain Local group scope?

Global groups hold users from their own domain (role groups); Domain Local groups are used to grant permissions on resources in their domain and can contain globals from any trusted domain (AGDLP).

Stretch Goal: Bulk Create from CSV

Save as C:\Lab\newhires.csv:

First,Last,Sam,Title
Jordan,Lee,jlee,Content Writer
Morgan,Diaz,mdiaz,SEO Specialist
Casey,Park,cpark,Graphic Designer
$pw = Read-Host -AsSecureString "Temp password for all new hires"
Import-Csv C:\Lab\newhires.csv | ForEach-Object {
    New-ADUser -Name "$($_.First) $($_.Last)" -GivenName $_.First -Surname $_.Last `
      -SamAccountName $_.Sam -UserPrincipalName "$($_.Sam)@lab.local" `
      -Title $_.Title -Department "Marketing" `
      -Path "OU=Marketing,DC=lab,DC=local" `
      -AccountPassword $pw -ChangePasswordAtLogon $true -Enabled $true
    Add-ADGroupMember -Identity "GG_Marketing_Share_RW" -Members $_.Sam
    Write-Host "Created $($_.Sam)"
}

Bonus: add -WhatIf for a dry run, and wrap in try/catch to log failures. Run this before cleanup (or recreate the OU/group first).
